Migration Accord — récompenses de quête

ExperienceReward → AccordGain · FHWHeritageGain · 6 tiers items
Pourquoi : la refonte canonique 2026 retire l'XP/Or des quêtes

Le pipeline ci-dessous est encore branché sur la struct historique FHWQuestReward qui expose ExperienceReward (int) et GoldReward (int). La doc UE5 (Quest System.md, HW Quest Component.md) flagge cette dette : ExperienceReward est loggé seulement, jamais appliqué. Aucun XP n'a jamais été gagné en jeu.

La refonte impose la translation suivante (V3 = doc seule, implémentation post-V4 — voir Migration Accord sur la page Architecture) :

ExperienceReward → AccordGain FLOAT 0-100 — pourcentage d'Accord gagné dans l'Ère active. Écrit dans UHWProgressionComponent::CurrentEraAccord (couche 3). Reset à zéro à chaque Souffle (l'Accord est éphémère, l'Héritage est permanent). Couche 3 · L'Accord
Nouveau : FHWHeritageGain Struct cible alimentant la couche 4 Héritage via UHWProgressionComponent : Title (titres permanents), LoreEntry (entrées encyclopédie), Recipe (recettes artisanales), AccessToArea (déblocages de zones). Toutes ces récompenses survivent au Souffle. Couche 4 · Héritage
GoldReward Conservé tel quel — la monnaie reste un mécanisme valide. Pas d'impact Migration Accord. Stable
ItemRewards (rareté gameplay 6 tiers) La TMap<FGameplayTag, int32> reste, mais les items distribués portent désormais une rareté gameplay canonique en 6 paliers : Commun · Inhabituel · Rare · Épique · Légendaire · Mythique (distincte de la classification visuelle T1-T7 ROG). La rareté biaise les drops selon la dimension dominante de l'Ère active. Items · 6 tiers
UnlockReward / ReputationRewards Conservés. UnlockReward bascule via IncrementProgress(QuestCompleted, ...) ; les ReputationRewards alimentent la Reconnaissance (privée, 9 religions canoniques) — distincte du Renom (public, mémoire collective au Souffle). Unlock · Reconnaissance
— Pas de breaking change C++ —

Les structs FHWQuestReward et UHWQuestData conservent leur interface C++. La translation est sémantique côté serveur OWS et côté UI. Le pipeline ci-dessous décrit le flux tel qu'il existe aujourd'hui dans le code, avec les annotations Migration Accord en surimpression.

Étape 1 — Créer un UHWQuestData

UPrimaryDataAsset · FHWQuestObjective · FHWQuestReward
Toute quête commence par un DataAsset décrivant ses objectifs, récompenses et conditions

UHWQuestData est un UPrimaryDataAsset défini dans Source/HybeliorWorld/Public/Progression/HWQuestData.h. Il centralise l'identifiant, le type, les objectifs, les récompenses, les prérequis et les liens dialogue. Le PNJ qui propose la quête se contente de référencer le QuestID (voir Pipeline NPC).

Le type est porté par l'enum EHWQuestType qui conditionne le classement journal et le comportement de répétition.

QuestID FGameplayTag — identifiant unique référencé par dialogue, progression et indicateurs PNJ.
QuestName / QuestDescription FText — affichés dans le journal et le Quest Tracker.
QuestType EHWQuestType — MainStory, Side, Daily, Weekly, Hidden, Chain.
RecommendedLevel Champ technique interne conservé pour matchmaking et scaling serveur. Selon la Migration Accord, il n'est jamais exposé au joueur dans le HUD ni le journal — la difficulté ressentie est désormais portée par l'Accord de l'Ère active.
Objectives / Rewards TArray<FHWQuestObjective> et FHWQuestReward — détaillés dans les blocs ci-dessous.
PrerequisiteQuests TArray<FGameplayTag> — quêtes devant être Completed avant que celle-ci ne soit acceptable.
NextQuestInChain FGameplayTag — quête suivante découverte automatiquement à la complétion (chaînes Chain).
DiscoveryConditions TArray<FHWUnlockCondition> — destiné à révéler les quêtes Hidden. Dette technique connue : ces conditions ne sont jamais vérifiées au runtime (TODO non résolu, voir HW Quest Component.md § Incohérences #2).
QuestGiverTag · AcceptDialogueID · CompleteDialogueID FGameplayTag — pointeurs vers le PNJ donneur et les dialogues d'acceptation / remise (voir Pipeline NPC).
TimeLimitSeconds Champ déclaré mais jamais utilisé dans le code (dette #3). Aucune quête temporisée ne peut échouer aujourd'hui.
bRepeatable Booléen — autorise la réacceptation après complétion ou abandon.
— Structure FHWQuestObjective —

Description — texte affiché au joueur. ConditionType — EHWConditionType (Kill, Collect, LocationVisited, ItemObtained, ComboAchieved, etc., 11 valeurs partagées avec UHWProgressionComponent). SubjectTag — FGameplayTag identifiant la cible (type de mob, item, zone).

TargetValue — quantité requise. Visibility — Visible / Hint / Hidden / RevealOnProgress. RequiredLocation — zone optionnelle (non validée au runtime — dette #4). CurrentProgress — runtime, clampé entre 0 et TargetValue.

— Structure FHWQuestReward (annotée Migration Accord) —

ExperienceReward (int — loggé seulement) — à réinterpréter en AccordGain (FLOAT 0-100) côté UHWProgressionComponent::CurrentEraAccord. GoldReward — monnaie, conservée. ItemRewards — TMap<FGameplayTag, int32>, items concrets en 6 tiers gameplay (Commun → Mythique).

UnlockReward — FGameplayTag bascule un déblocage via IncrementProgress(QuestCompleted, ...). ReputationRewards — TMap<FGameplayTag, float>, gains de Reconnaissance par faction (9 religions canoniques côté lore). Cible Migration Accord : ajout d'un nouveau champ FHWHeritageGain (Title, LoreEntry, Recipe, AccessToArea) alimentant la couche 4 Héritage.

— Configuration AssetManager (dette technique #5) —

UHWQuestData et UHWUnlockDefinition ne sont pas enregistrés dans DefaultGame.ini via PrimaryAssetTypesToScan. L'AssetManager peut donc échouer à les découvrir au boot. Configuration cible (à ajouter post-V4) : +PrimaryAssetTypesToScan=(PrimaryAssetType="QuestData", AssetBaseClass="/Script/HybeliorWorld.HWQuestData", Directories=((Path="/Game/Data/Quests"))).

Étape 2 — Biais par l'Ère active

Les Ères · 6 dimensions · pondération de découverte
Le Souffle change l'Ère — l'offre de quêtes change avec lui

À chaque Souffle cosmique (Petit / Grand / Cardinal), une nouvelle Ère s'installe avec ses 6 dimensions paramétriques (cosmique, élémentaire, sociale, etc.). Cette Ère biaise la disponibilité et la pondération des quêtes : les QuestType et les SubjectTag alignés avec la dimension dominante de l'Ère sont privilégiés dans la découverte (PNJ donneurs, indicateurs prioritaires, drops augmentés sur les ItemRewards élémentaires correspondants).

Concrètement, la pondération s'applique à plusieurs étages : (1) le Quest Giver Tag des PNJ filtré par les EraActiveTags du GlobalDataService, (2) le multiplicateur d'AccordGain appliqué côté UHWProgressionComponent, (3) la rareté des ItemRewards tirée via UHWLootTable en biaisant le RarityWeight selon l'élément dominant de l'Ère.

EraActiveTags Tags répliqués via GlobalDataService décrivant l'Ère en cours (dimension dominante, élément dominant, archétype).
EraAccordMultiplier Coefficient appliqué à l'AccordGain brut d'une quête selon l'alignement entre son thème (QuestGiverTag) et l'Ère active. Une quête en parfaite résonance peut accorder x1.5 ; en dissonance, x0.5.
Quest Discovery Bias Le système de découverte privilégie les quêtes alignées avec l'Ère pour les indicateurs PNJ, sans masquer les autres — l'offre reste lisible mais respire au rythme du Souffle.

Étape 3 — Découverte de la quête

DiscoverQuest · AssetManager · QuestDataCache
La quête est chargée en mémoire et passe en statut Discovered

DiscoverQuest(QuestID) (cf. HWQuestComponent.cpp) charge le UHWQuestData via UAssetManager::Get() et met le pointeur en cache dans QuestDataCache (TMap<FGameplayTag, TObjectPtr<UHWQuestData>>) pour éviter les chargements redondants.

Le statut passe à Discovered et le delegate OnQuestDiscovered est broadcast (UI, autres systèmes). La découverte peut être déclenchée par : interaction PNJ, exploration (AHWLocationTrigger via MarkLocationVisited), ou cascade de chaîne (NextQuestInChain auto à la complétion d'une quête précédente).

EHWQuestStatus::Unknown (0) État initial — la quête n'a jamais été rencontrée par le joueur. Défaut
EHWQuestStatus::Discovered (1) Révélée (via PNJ, exploration ou chaîne) mais pas encore acceptée. Découverte
EHWQuestStatus::Active (2) Acceptée et en cours — les objectifs sont suivis activement. En cours
EHWQuestStatus::Completed (3) Tous les objectifs remplis et récompenses distribuées. Terminée
EHWQuestStatus::Failed (4) Échec — réservé aux quêtes temporisées (non actif aujourd'hui, dette #3). Échec
EHWQuestStatus::Abandoned (5) Le joueur a abandonné — peut réaccepter si bRepeatable. Abandonné

Étape 4 — Acceptation de la quête

AcceptQuest · Prérequis · Réplication
L'acceptation passe par le dialogue et valide toutes les conditions

Le joueur accepte la quête via un choix de dialogue portant l'ActionTag = "Action.AcceptQuest" avec ActionParameter = QuestID. AHWPlayerController::HandleDialogueAction() route l'action vers QuestComp->AcceptQuest(QuestID).

AcceptQuest(QuestID) Point d'entrée — valide le QuestID, vérifie le statut (pas Active ni Completed sauf bRepeatable), appelle ArePrerequisitesMet(), passe le statut à Active.
ArePrerequisitesMet() Itère sur PrerequisiteQuests et vérifie que chacune est au statut Completed.
MakeObjectiveKey() Génère la clé de progression au format "{QuestID}_{ObjectiveIndex}" — utilisée dans les TMap répliqués.
Rep_QuestStatuses / Rep_QuestProgress Tableaux répliqués (workaround #8 — les TMap ne sont pas répliquées nativement). Synchronisent statuts et progression entre serveur et client.
OnQuestAccepted Delegate broadcast après acceptation — notifie tracker UI, journal et indicateurs PNJ.

Étape 5 — Suivi de la progression

UpdateQuestProgress · ConditionType · SubjectTag
Chaque action du joueur est évaluée contre les objectifs actifs

UpdateQuestProgress(ConditionType, SubjectTag, Amount) est appelé par les systèmes de jeu (combat, collecte, exploration, AHWLocationTrigger) chaque fois qu'une action pertinente se produit. La méthode itère sur les quêtes Active et compare ConditionType + SubjectTag de chaque objectif.

Quand une correspondance est trouvée, la progression est incrémentée (clampée entre 0 et TargetValue), synchronisée dans les tableaux répliqués, et OnQuestObjectiveUpdated est broadcast.

UpdateQuestProgress() Itère sur les quêtes Active, matche les objectifs par ConditionType + SubjectTag, incrémente la progression.
Sources d'événements Combat (OnKill, réactions élémentaires), inventaire (OnItemAcquired), exploration (AHWLocationTrigger::OnOverlap serveur), interaction (IInteractable).
Clamp progression CurrentProgress toujours clampé entre 0 et TargetValue — pas de dépassement.
OnQuestObjectiveUpdated Delegate broadcast avec (QuestID, ObjectiveIndex, NewProgress) — le tracker UI se met à jour en temps réel.
CheckQuestCompletion(QuestID) Appelé automatiquement après chaque mise à jour — vérifie si tous les objectifs atteignent TargetValue.

Étape 6 — Complétion et récompenses

CheckQuestCompletion · ApplyQuestRewards · AccordGain · Heritage
La complétion déclenche les récompenses et peut initier la quête suivante

CheckQuestCompletion(QuestID) vérifie CurrentProgress >= TargetValue pour chaque objectif. Si tous remplis, le statut passe à Completed et ApplyQuestRewards() distribue les composantes de FHWQuestReward.

La complétion signale le système de progression via ProgressionComp->IncrementProgress(EHWConditionType::QuestCompleted, QuestID, 1.0f). Si NextQuestInChain est défini, DiscoverQuest(NextQuestInChain) est appelé — la chaîne se propage automatiquement.

CheckQuestCompletion() Vérifie tous les objectifs — retourne vrai si CurrentProgress >= TargetValue pour chacun. Garde-fou
ApplyQuestRewards() — état actuel Distribue GoldReward, ItemRewards, UnlockReward, ReputationRewards. ExperienceReward seulement loggé (dette #1) — voir Migration Accord. Code actuel
ApplyQuestRewards() — cible Migration Accord Écrit AccordGain dans UHWProgressionComponent::CurrentEraAccord (couche 3, multiplié par EraAccordMultiplier selon alignement Ère). Bascule FHWHeritageGain (Title, LoreEntry, Recipe, AccessToArea) en couche 4 Héritage. Cible post-V4
IncrementProgress(QuestCompleted, ...) Signale au UHWProgressionComponent que la quête est complétée — déclenche en cascade les UHWUnlockDefinition conditionnés. Progression
NextQuestInChain Si défini, DiscoverQuest(NextQuestInChain) est appelé automatiquement. Note dette #6 : les DiscoveryConditions de la quête suivante ne sont pas vérifiées — les chaînes Hidden ne sont jamais découvertes. Chaîne
OnQuestCompleted Delegate broadcast à la complétion — met à jour journal, tracker et indicateurs PNJ. Notification

Étape 7 — Abandon de quête

AbandonQuest · Nettoyage · Réacceptation
Le joueur peut abandonner une quête active à tout moment

AbandonQuest(QuestID) passe le statut à Abandoned et nettoie toutes les entrées de progression associées dans les tableaux répliqués.

Si bRepeatable est activé sur le UHWQuestData, le joueur peut réaccepter la quête auprès du PNJ donneur. La progression repart de zéro. Note Migration Accord : un AccordGain partiellement engrangé via objectifs intermédiaires reste acquis (l'Accord ne se rétracte pas), mais le titre permanent (couche 4) ne se déclenche qu'à la complétion intégrale.

Étape 8 — Persistance OWS

SerializeQuests · JSON · clé "QuestProgress"
Les quêtes sont sérialisées en JSON et sauvegardées via le backend OWS

SerializeQuests() convertit l'état complet en JSON : {"statuses": {tag: int}, "progress": {key: float}}. DeserializeQuests(JSON) reconstruit les TMap et synchronise les tableaux répliqués Rep_QuestStatuses / Rep_QuestProgress.

SaveQuestProgress() appelle AddOrUpdateCustomCharacterData("QuestProgress", JSON) sur l'API OWS (via OWSPlayerControllerComponent). La sauvegarde automatique est portée par AutoSaveProgressionTimer (5 min loop) côté AHWPlayerController, plus un flush obligatoire au logout (ordre critique : Bag → Equipment → 3 CharacterData → Progression/Quest pour éviter la race condition).

SerializeQuests() Convertit les TMap de statuts et de progression en chaîne JSON compacte.
DeserializeQuests(JSON) Reconstruit les TMap depuis le JSON et synchronise Rep_QuestStatuses / Rep_QuestProgress.
SaveQuestProgress() Appel backend via AddOrUpdateCustomCharacterData("QuestProgress", JSON) — persistance côté serveur OWS .NET.
Auto-save Sauvegarde automatique toutes les 5 minutes (AutoSaveProgressionTimer) + flush obligatoire au logout.

Étape 9 — Affichage UI

UHWQuestTrackerWidget · Delegates · 5 quêtes max
Le tracker affiche jusqu'à 5 quêtes actives en temps réel

UHWQuestTrackerWidget est initialisé via InitializeQuestTracker(QuestComponent) et s'abonne aux 4 delegates du composant. Le widget plafonne à MaxDisplayedQuests = 5. Le journal complet (illimité) est porté par un widget séparé.

Note Migration Accord : aucun nombre RecommendedLevel ni ExperienceReward n'est affiché dans le tracker post-refonte. La récompense visible est l'AccordGain (% par Ère) et les éléments d'Héritage (titres, recettes).

InitializeQuestTracker() Bind les delegates OnQuestAccepted, OnQuestObjectiveUpdated, OnQuestCompleted, OnQuestDiscovered.
OnQuestAdded Blueprint Event — ajoute une nouvelle entrée avec nom et objectifs.
OnObjectiveUpdated(Progress, Target) Blueprint Event — met à jour la barre de progression de l'objectif en temps réel.
OnQuestCompleted Blueprint Event — affiche notification de complétion et retire la quête du tracker.
OnQuestDiscovered Blueprint Event — affiche notification de découverte et propose au joueur de suivre la quête.
GetQuestObjectives(QuestID) Retourne la liste des objectifs avec leur progression actuelle — utilisé pour le rendu détaillé du journal.

Étape 10 — Intégration Progression et Héritage

UHWProgressionComponent · UHWUnlockDefinition · couche 4
La complétion de quêtes alimente le moteur d'Héritage

Chaque quête complétée déclenche UHWProgressionComponent::IncrementProgress(QuestCompleted, QuestID, 1.0f). Cet événement est consommé par les UHWUnlockDefinition qui définissent une condition QuestCompleted et accordent leurs EHWRewardType en cascade.

Selon la refonte canonique (voir HW Progression Component.md), UHWProgressionComponent devient conceptuellement le moteur d'Héritage (couche 4 de L'Accord) : c'est ici que se déclenchent les Title, LoreEntry et AccessToArea qui jalonnent la trace permanente du personnage. Ces récompenses survivent au Souffle ; à l'inverse, l'AccordGain (couche 3) se dissipe à chaque cycle cosmique.

IncrementProgress(QuestCompleted, QuestID, 1.0) Enregistre la complétion dans le ProgressionComponent — sert de déclencheur en cascade pour CheckAllUnlocks(). Progression
UHWUnlockDefinition (QuestCompleted) DataAsset de déblocage conditionné par la complétion d'une quête — accorde les EHWRewardType : Title, Recipe, LoreEntry, AccessToArea, Ability, StatBonus, etc. Déblocage
FHWHeritageGain (cible Migration Accord) Struct cible regroupant les composantes Héritage d'une récompense de quête — voir Étape 6. Branchée sur les mêmes EHWRewardType que UHWUnlockDefinition, mais accordée directement par ApplyQuestRewards() sans passer par une condition unlock séparée. Héritage · Couche 4
3 nouveaux types EHWConditionType (post-V4) AccordReached (palier 25/50/75/100), EraConcorded (titre permanent à la fin d'Ère 100 %), SouffleSurvived (trace par Souffle traversé). Ouvrent la voie à des unlocks rythmés sur le cycle cosmique. Cibles
GetNPCIndicator() via Progression Les indicateurs PNJ (! / ? / ? doré) utilisent le ProgressionComponent pour déterminer les tags d'état de quête. Indicateur
Dialogues conditionnels Les dialogues vérifient les déblocages de progression pour exposer des branches narratives spécifiques (par exemple, ouvertes uniquement après une chaîne de quêtes ou un titre Héritage). Dialogue · Condition

Dette technique recensée

8 incohérences · HW Quest Component.md
Pour transparence — dettes connues du pipeline actuel

Le pipeline ci-dessus reflète l'état du code à V3 avec ses imperfections recensées dans la doc UE5. Les dettes ne bloquent pas le boucle de jeu nominale mais conditionnent la roadmap post-V4.

#1 · ExperienceReward / GoldReward Loggés seulement, jamais accordés au joueur. Résolution = Migration Accord (translation en AccordGain + FHWHeritageGain).
#2 · DiscoveryConditions jamais vérifiées Les quêtes Hidden ne se découvrent jamais automatiquement — TODO non résolu.
#3 · TimeLimitSeconds non utilisé Aucune quête temporisée ne peut échouer ; le statut Failed n'est jamais atteint.
#4 · RequiredLocation non validé Le champ existe sur FHWQuestObjective mais n'est pas vérifié au runtime — un objectif est progressable depuis n'importe où.
#5 · PrimaryAssetType non enregistrés QuestData et HWUnlockDefinition manquants dans DefaultGame.ini — l'AssetManager peut ne pas découvrir les assets.
#6 · DiscoveryConditions + NextQuestInChain Les chaînes Hidden ne sont jamais découvertes (combine #2 et #5).
#7 · Unlock → Quête non notifié La progression appelle les quêtes (QuestCompleted) mais l'inverse n'existe pas — flux unidirectionnel.
#8 · TMap non répliquée nativement Workaround : Rep_QuestStatuses et Rep_QuestProgress en TArray reconstitués côté client.
