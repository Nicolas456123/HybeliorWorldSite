Architecture GAS

Gameplay Ability System · UE 5.4
Fondations

Le combat repose sur le Gameplay Ability System d'Unreal 5.4, étendu par des classes C++ HW. Cette page décrit la couche fondation : ASC, AttributeSet, Effects globaux, Réactions élémentaires, Tags. Les pages voisines détaillent les pipelines :

Pipeline Ability (création/activation d'une ability, Tasks asynchrones), Pipeline Combo (combos, movesets, Maîtrise d'arme), Pipeline Mob (IA, spawn, pool). Cette factorisation évite les doublons.

UHWAbilitySystemComponent ASC custom héritant de UAbilitySystemComponent. Route les inputs joueur vers les abilities via tags (AbilityInputTagPressed/Released), gère le batch RPC serveur (ShouldDoServerAbilityRPCBatch → true : utile pour les abilities à cycle court qui se terminent dans la même frame), et consulte le UHWAbilityTagRelationshipMapping. ASC · Input · Batch
UHWGameplayAbility Classe de base de toutes les abilities. Expose EHWAbilityActivationPolicy (OnInputTriggered, WhileInputActive, Passive) et EHWAbilityActivationGroup (Independent, Exclusive_Replaceable, Exclusive_Blocking). Détails création/activation : voir Pipeline Ability. Base · Policy · Group
UHWAbilityTagRelationshipMapping DataAsset déclarant les relations entre tags : AbilityTagsToBlock, AbilityTagsToCancel, ActivationRequiredTags, ActivationBlockedTags. Lookup O(n) — acceptable jusqu'à ~50 entrées. Centralise les règles d'activation sans coder en dur les dépendances. DataAsset · Règles
UHWGameplayAbilitySet DataAsset de bundle. Octroie en une opération un ensemble d'abilities, d'effets de gameplay et d'attribute sets à un personnage. FHWAbilitySet_GrantedHandles::TakeFromAbilitySystem() révoque tous les grants d'un coup. DataAsset · Grant
FHWGameplayTags Singleton C++ initialisé par UHWAssetManager::StartInitialLoading. Déclare 93 tags natifs répartis en 17 catégories (inputs, états, dégâts, réactions, armes, ressources, UI). API FindTagByString(string, bMatchPartialString). Tags · Singleton

Combat Attribute Set

Ressources · 8 stats brutes canoniques
UHWCombatAttributeSet

Hérite de UHWAttributeSet → UAttributeSet. Déclare l'ensemble des attributs numériques répliqués du personnage de combat. Hooks serveur :

PreGameplayEffectExecute() — clamping, détection critique par parité, type de dégât élémentaire, suppression/application de conditions, réduction par Defense. PostGameplayEffectExecute() — application définitive sur Health, déclenchement des événements de mort, mise à jour des barres UI.

Refonte 2026 — alignement canon Personnage

La doc canon (Personnage.md) impose 8 stats brutes Couche 1 (Vigueur, Vivacité, Endurance, Acuité, Esprit, Résonance, Mémoire, Verbe) et 4 stats fondamentales Couche 0 (Vitalité, Souffle, Présence, Conscience). L'AttributeSet C++ actuel utilise encore les 3 attributs hérités D&D Strength / Agility / Constitution — voir Migration Accord pour le mapping et le phasage.

Mapping prévu : Strength → RawStat_Vigueur, Agility → RawStat_Vivacite, Constitution → RawStat_Endurance. Les 5 stats manquantes côté code (Acuité, Esprit, Résonance, Mémoire, Verbe) seront ajoutées en colonnes nouvelles. Aucun breaking change OWS — les attributs existants sont conservés et marqués comme techniques internes.

Compression Le Souffle (à implémenter post-V4)

À chaque Souffle cosmique (cycle Petit / Grand / Cardinal — voir Gameplay : Monde), UHWGameplayEffectExecutionCalc appliquera la règle canonique : pour toute stat brute Couche 1, si RawStat > 50 alors RawStat = 50 + (RawStat − 50) × 0.7. La compression ramène 30 % de l'excès vers le seuil 50 — c'est le mécanisme anti-power-creep central. Implémentation prévue post-V4 ; refonte sémantique seule en V3.

Ressources vitales

Health · MaxHealth · HealthRegenRate Défauts : 100 / 1000 / 100/5s. Health clampé entre 0 et MaxHealth dans PreGameplayEffectExecute. Atteindre 0 déclenche la logique de mort. Réplication COND_None / COND_OwnerOnly.
Mana · MaxMana · ManaRegenRate Défauts : 130 / 1500 / 200/5s. Consommé par les compétences de Voie. Sans Voie active, le pool ne porte aucun usage gameplay côté joueur. Réplication COND_OwnerOnly.
Stamina · MaxStamina · StaminaRegenRate Défauts : 100 / 100 / 10/5s. Consommé par attaques, esquives, sprint, parades tenues. Note canon : la formule joueur est Stamina max = Souffle (Couche 0) + Endurance (Couche 1) × 2 — l'AttributeSet C++ actuel utilise une valeur fixe (mapping prévu via Migration Accord).
Energy · MaxEnergy · EnergyRegenRate Défauts : 100 / 100 / 0/5s. Ressource auxiliaire pour abilities spécifiques. Pas de regen passive par défaut.

Statistiques de combat (état actuel C++)

Strength → Vigueur (canon) Défaut 10. Formule dérivée : Attack = min(Strength × 10, 9999). Côté canon, à mapper vers RawStat_Vigueur.
Agility → Vivacité (canon) Défaut 10. Formule dérivée : CritRate = clamp(Agility × 0.5, 0, 100). Côté canon, à mapper vers RawStat_Vivacite.
Constitution → Endurance (canon) Défaut 10. Formule dérivée : MaxHealth = Constitution × 100. Côté canon, à mapper vers RawStat_Endurance (le canon Personnage scinde aussi PV vs Stamina selon Vigueur vs Endurance).
Attack · Defense Puissance d'attaque dérivée et coefficient défensif [0.0–1.0]. Defense applique Damage -= Damage × Clamp(Defense, 0, 1).
CritRate · CritDamage Défauts 0.05 et 0.5 (5 % chance, +50 % bonus). Évalués par UHWDamageGameplayEffect.
Stats canoniques manquantes côté code Acuité, Esprit, Résonance, Mémoire, Verbe ne sont pas encore représentées dans UHWCombatAttributeSet. Ajout prévu via Migration Accord (Phase C).

Attributs transitoires (non répliqués)

Damage Valeur intermédiaire dans le pipeline. Appliquée comme −Health dans PostGameplayEffectExecute. Servait aussi à l'encodage critique par parité (voir UHWDamageGameplayEffect ci-dessous).
Healing Valeur intermédiaire de soin. Appliquée comme +Health dans PostGameplayEffectExecute.

Effects — Dégâts & Conditions

UHWDamageGameplayEffect · ExecutionCalc
Pipeline d'application des dégâts

Les dégâts traversent une chaîne complète : GA → UHWDamageGameplayEffect → UHWGameplayEffectExecutionCalc → PreGameplayEffectExecute → réaction élémentaire → PostGameplayEffectExecute → OnHealthChange.

UHWDamageGameplayEffect Classe parente de tous les GE de dégât. Configure UTargetTagRequirementsGameplayEffectComponent pour ignorer les cibles taguées Combat.State.IFrame. Contient le système de critiques (CritRate / CritDamage). GE · Dégâts
UHWGameplayEffectExecutionCalc Calculator d'exécution serveur. Capture Attack, MaxHealth, CritRate, CritDamage de la source (snapshot). Calcule BaseDamage = Attack + MaxHealth (formule à reviser — mentionnée comme « surprenante » dans la doc canon, perturbe l'équilibrage). Execution · Serveur
UHWCombatDataSubsystem World Subsystem centralisant tables de données et coefficients de balance. Accessible par tous les calculateurs et abilities via UHWGameplayAbility::GetFloatValueFromCombatData(FString). Subsystem · Data
— Encodage critique par parité —

Le critique est signalé en forçant la magnitude finale à un nombre impair (la valeur normale est paire). Lecture côté PreGameplayEffectExecute : si magnitude % 2 == 1 alors c'est un critique. Méthode fragile si la formule de dégâts évolue — point d'attention canon.

Effects — États Élémentaires

Pattern Applicateur + DoT
Deux couches : applicateur (tag) + effet actif (DoT)

Les états élémentaires utilisent un pattern à deux GE séparés. L'applicateur (GE_Apply*) accorde le tag d'état avec stacking AGGREGATE_BY_TARGET et REFRESH_ON_SUCCESSFUL_APPLICATION. L'effet actif (GE_*Effect) gère les modificateurs d'attributs et les dégâts par tick. Cette séparation permet de vérifier le tag sans dépendre du DoT.

Burning GE_ApplyBurningFor10Seconds (durée effective 6s, tag Combat.State.Burning) + GE_BurningEffect (DoT 10s, tick 1.0s, +1.0 Damage/tick).
Wet GE_ApplyWetFor10Seconds (10s, tag Combat.State.Wet). Pas de DoT — état de marquage uniquement, prérequis pour Freeze, ElectroCharge, Vaporize.
Cold GE_ApplyColdFor6Seconds (6s, tag Combat.State.Cold). Marqueur intermédiaire avant transition vers Frozen.
Frozen GE_ApplyFrozenFor4Seconds (4s, tag Combat.State.Frozen, CLEAR_ENTIRE_STACK à l'expiration). État sévère court — fenêtre de Shatter.
Electrified · Charged Tags Combat.State.Electrified et Combat.State.Charged existent dans CombatTags, mais aucun GE Blueprint n'est encore créé. ApplyElectrifiedGameplayEffect et ApplyChargedGameplayEffect sont null dans le GameMode par défaut — voir Anomalies.
IFrame · DodgedRecently GE_DodgeForwardIFrame (0.5s) et GE_DodgeBackwardIFrame (~0.6s) accordent Combat.State.IFrame. GE_DodgedRecently (0.5s) accorde Combat.State.DodgedRecently, requis comme ActivationRequiredTag pour les abilities de contre-esquive.
— Configuration via GameMode —

AHWGameMode expose 6 TSubclassOf<UGameplayEffect> (ApplyColdGameplayEffect, ApplyBurningGameplayEffect, ApplyWetGameplayEffect, ApplyElectrifiedGameplayEffect, ApplyFrozenGameplayEffect, ApplyChargedGameplayEffect). BP_HybeliorGameMode doit configurer ces propriétés. Risque silent fail si le GameMode actif n'est pas BP_HybeliorGameMode — les GE élémentaires ne se chargent alors pas.

Réactions Élémentaires

8 réactions · Système statique
UHWElementalReactionSystem

Système statique centralisé. Évalue les interactions entre 4 éléments (Fire, Water, Ice, Lightning) et 6 conditions (Burning, Wet, Cold, Frozen, Electrified, Charged). Appelé depuis UHWCombatAttributeSet::HandlePreExecuteEffectDamage (pas dans l'ExecutionCalc — pour éviter une double-application).

API : FHWElementalReactionResult CheckReaction(IncomingDamageType, TargetActiveConditions) retourne le résultat (multiplicateur, condition à appliquer/retirer, AoE éventuel) ; void ApplyReaction(TargetASC, Result) applique l'effet.

Vaporize Wet + Fire (ou inverse). Multiplicateur ×1.5 sur l'attaque déclencheuse. Retire l'état Wet de la cible. Wet + Fire · ×1.5
Melt Cold (ou Frozen) + Fire. ×1.3. Sur cible Frozen, applique aussi Wet après réaction (bApplyWetAfterReaction). Cold + Fire · ×1.3
Overload Charged + Fire. ×1.5 + AoE rayon 500. Repousse les ennemis proches. Charged + Fire · AoE
Freeze Wet + Ice (ou Cold + Ice). Applique Combat.State.Frozen via GE_ApplyFrozenFor4Seconds. La cible gelée est vulnérable au Shatter. Wet + Ice · CC
Superconduct Cold + Lightning. Réduit Defense de 30% pendant une durée prolongée. Préparation pour frappes lourdes. Partiellement implémenté : certains cas restent placeholder. Cold + Lightning · Def↓
ElectroCharge Wet + Lightning. ×1.2 + applique Combat.State.Charged (ou Electrified selon source). DoT et propagation aux cibles mouillées proches. Wet + Lightning · DoT
Firestorm (placeholder) Burning + Lightning ou Electrified + Fire. Doit propager les flammes sur zone avec dégâts amplifiés. Non implémenté dans l'EnumValue. Placeholder
Shatter (placeholder) Attaque physique lourde sur cible Frozen. Doit briser la glace avec dégâts bonus proportionnels à Defense de la cible. Non implémenté dans l'EnumValue. Placeholder
Anomalies connues

3 réactions placeholder (Firestorm, Superconduct partiel, Shatter). Relation Cold ↔ Frozen floue côté design. ApplyElectrifiedGameplayEffect et ApplyChargedGameplayEffect null dans le GameMode. GE_FireballDamageEffect a un tag d'effet Combat.DamageType.Water suspect (Feu ≠ Eau). GE_LightningStormDamage n'a aucun tag de type — interactions élémentaires non fonctionnelles. GE_TestDamage50 à retirer avant prod.

Système de Tags

93 tags natifs · 5 DataTables
Source unique de vérité

Les tags natifs sont initialisés en C++ (FHWGameplayTags::InitializeNativeTags) et alimentés par 5 DataTables sous /Game/AbilitySystem/Tags/ qui servent de source unique de vérité, enregistrées via UGameplayTagsManager.

AbilityTags (7) Échecs d'activation et événements (Ability.ActivateFail.IsDead/Cooldown/Cost/TagsBlocked/TagsMissing/Networking, Ability.Event.Combo).
CombatTags (35) États (Dead, Wet, Burning, Cold, Charged, Electrified, Frozen, IFrame, DodgedRecently, ReadyToFight, Blocking) ; types de dégâts (Fire, Water, Ice, Lightning, Falling) ; cooldowns ; SetByCaller (Strength, Attack, Speed, Agility, CritDamage, Intelligence, Constitution, MaxStamina, MaxHealth, MaxMana, Defense) ; flags critiques ; sets d'arme.
EquipementTags (22) 16 slots d'équipement (EquipementSlot.*) + 6 types d'arme (WeaponType.Unarmed, Bow, HandLeftAlone, HandRightAlone, TwoWeapon, GreatSword). Note canon : la liste de WeaponType côté code (6) est plus restreinte que les 13 types d'arme côté gameplay — alignement à prévoir.
InputTags (24) 7 tags ability (NormalAbility1/2, SpecialAbility1, Dash, WeaponLeft/Right, ReadyToFight) + 7 inputs divers (Crouch, Move, Interact, Sprint, WalkRun, Aiming, FirstCamera) + 10 états de mouvement (MovementState.*).
GameplayCueTags (2) GameplayCue.Test, GameplayCue.LightningStorm.Strike. Réservé à l'expansion VFX/SFX.
Tags d'invulnérabilité Combat.State.Invulnerable et Combat.State.IFrame sont consommés en priorité dans PreGameplayEffectExecute (Invulnerable force la magnitude à 0 ; IFrame est filtré côté GE de dégât via UTargetTagRequirementsGameplayEffectComponent).

Migration Accord — Côté Combat

Refonte sémantique 2026
Stratégie de migration parallèle

La doc canon (L'Accord, Le Souffle, Les Ères) abandonne le concept de CharacterLevel/XP classique au profit du système 5 couches : Stats brutes → Maîtrises → L'Accord → Héritage → Identité. La migration suit une stratégie parallèle non bloquante — les tables OWS existantes restent en place, les nouvelles colonnes s'ajoutent.

Côté combat, l'impact est documenté dans Migration Accord.md. Aucun breaking change réseau ni OWS ; FUserCharacter garde tous ses champs ; CharacterLevel/XP deviennent invisibles côté HUD mais continuent de fonctionner techniquement.

Phase A — Schéma SQL Ajout de 4 colonnes : CurrentEraAccord FLOAT (0–100), ConcordedErasCount INT, EraAccordsHistory JSON, CurrentMasteryRustLevel FLOAT. ALTER TABLE ADD COLUMN DEFAULT 0 non bloquant.
Phase B — Lecture/écriture client UHWProgressionComponent lit/écrit CurrentEraAccord sur les events gameplay pertinents. UI bascule sur Accord. CharacterLevel et XP deviennent purement internes.
Phase C — 8 stats brutes Nouvelles colonnes RawStat_Vigueur, RawStat_Vivacite, RawStat_Endurance, RawStat_Acuite, RawStat_Esprit, RawStat_Resonance, RawStat_Memoire, RawStat_Verbe (FLOAT 0–150). Strength/Agility/Constitution projetés dessus pour rétrocompatibilité.
Phase D — Compression Souffle Implémentation dans UHWGameplayEffectExecutionCalc : pour toute stat brute > 50, ramener 30 % de l'excès vers 50. Côté combat, c'est ce qui resserre les écarts à chaque cycle cosmique.
Phase E — 5 paliers Maîtrise La courbe XP × 1.15^N de UHWWeaponMasteryComponent est remplacée par 5 seuils discrets (Novice → Initié → Adepte → Expert → Maître) + une rouille post-Souffle (−15 % une semaine, dissipée par usage). Voir Pipeline Combo pour le détail.
— Note de vocabulaire : Souffle ≠ Stamina —

Le mot Souffle a deux sens dans Hybélior : (a) une stat fondamentale Couche 0 qui dimensionne le pool de Stamina (capacité d'effort général d'un mortel) ; (b) le cycle cosmique qui rééquilibre périodiquement le monde (Petit / Grand / Cardinal). Côté code, Stamina reste l'attribut anglais qui nomme la barre de combat — il ne faut pas le renommer en « Souffle » pour éviter la collision sémantique avec le concept cosmique.
