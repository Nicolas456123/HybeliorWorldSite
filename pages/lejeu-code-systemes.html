Systèmes Transverses C++

Personnages · Inventaire · Progression · Quêtes
Périmètre de cette page

Cette page documente les systèmes transverses du code C++ — ce qui n'est ni un pipeline (Ability, Combo, Mob, NPC, Item, Quest), ni le code combat GAS (couche AttributeSet / Effects / Réactions). On y trouve les classes de personnage, les composants gameplay attachés au PlayerCharacter (Inventaire, Progression, Quête), et le contrôleur joueur qui orchestre l'ensemble.

Pages voisines : Code GAS (couche fondation combat), Pipelines (workflow détaillé d'une fonctionnalité), Code UI (HUD, widgets, inputs, interactables). Pour la migration Le Souffle / L'Accord / Les Ères, voir Architecture et Code GAS.

Hiérarchie des Personnages

AHWCharacter · AHWGASCharacter · AHWGASPlayerCharacter
Trois classes — une lignée

Toutes les entités de combat (joueurs et créatures) descendent de ACharacter via une chaîne à 3 maillons : AHWCharacter (base commune, anatomie, ciblage, animations) → AHWGASCharacter (intégration ASC + AttributeSet) → AHWGASPlayerCharacter (joueur) ou AHWGASEntityCharacter (créature/PNJ — détaillé dans Pipeline Mob et Pipeline NPC).

AHWCharacter Base commune. Hérite de ACharacter. Déclare les structs répliquées FHWOftenChangeCharacterData (Vie/Mana/Stamina/Energy actuels), FHWChangeCharacterData (maxima, regen, attributs, niveau), FHWCharacterAppearance/FHWCharacterAppearanceCE (apparence dual legacy/CE), FHWRarelyChangeCharacterData (métier, religion, guilde, peurs, titres). Expose 10 anatomies via EHWAnatomy (HumanFemale/Male Adult+Child, Dwarf, Elf, Orc) et l'API SetupURO() qui configure la fréquence d'animation par LOD. Base · Anatomie · URO
AHWGASCharacter Couche d'intégration GAS. Implémente IAbilitySystemInterface. Composants : UHWAbilitySystemComponent (privé, exposé via GetAbilitySystemComponent()) + UHWCombatAttributeSet + MeleeHitBox. Double init GAS requis par la réplication standard : PossessedBy() côté serveur, OnRep_Controller() côté client. Expose les BlueprintNativeEvent HealthChanged, ManaChanged, StaminaChanged, EnergyChanged, OnInflictDamage qu'overrident les BP UI. GAS · ASC · Attribute Set
AHWGASPlayerCharacter Personnage joueur. Caméras FPS+TPS avec SpringArm. 9 slots skeletal mesh apparel (Bow, Chest, Pants, Cloak, Helms, Boots, Head, Hairstyle, Shoulders). Composants gameplay : Progression, Quest, Combo (Pipeline Combo), WeaponMastery, Dialogue (Pipeline NPC), SkillBar, Buoyancy. Logique BeginPlay/Tick migrée de BP en C++ depuis 2026-04-07 — nameplate, respawn teleport, login widget, visibilité arc, mise à jour ciblage. SprintFlySpeed exposé en UPROPERTY. Dégâts de chute : seuil Velocity.Z <= -100, formule max(0, -Velocity.Z - 100) × 0.1 (note canon : ne tient pas compte de la défense — incohérence connue). Joueur · Caméras · Apparel
AHWGASEntityCharacter Personnage non-joueur (créatures, PNJ). Override OnHealthChange pour déclencher EntityDead() et rafraîchir la nameplate. Détaillé dans Pipeline Mob (IA, spawn, pool) et Pipeline NPC (dialogues, quêtes). Mob · PNJ · Voir Pipelines
Refonte 2026 — 8 stats brutes + 4 fondamentales

Le canon GDD impose deux couches de stats : Couche 0 auto-calculée (Vitalité, Souffle, Présence, Conscience) et Couche 1 par usage 0–150 (Vigueur, Vivacité, Endurance, Acuité, Esprit, Résonance, Mémoire, Verbe). Les 7 attributs actuels de UHWCombatAttributeSet seront mappés via Migration Accord : Strength → Vigueur, Agility → Vivacité, Constitution → Endurance ; les 5 stats canoniques manquantes (Acuité, Esprit, Résonance, Mémoire, Verbe) seront ajoutées en colonnes nouvelles. Voir Code GAS pour le détail AttributeSet et la compression Le Souffle.

— Structs préservées après refactor 2026-04-07 —

FHWMaterialSet (set de matériaux de peau) et FHWAnatomyProfile (profil anatomique : BodyMesh, HeadMesh, AnimInstanceClass, SkinMaterialSets) ont été déplacées depuis UHWCharacterCustomComponent (supprimé) vers HWCharacter.h. BP_PlayerCharacter_CE est désormais une coquille vide (0 vars, 0 logique) — toute la logique vit en C++.

Inventory Component

UHWInventoryComponent · 17 slots équipement
Deux instances montées sur PlayerController

UHWInventoryComponent est attaché au AHWPlayerController en deux instances distinctes : BagInventory (sac principal) et EquipmentInventory (équipement porté). Chaque instance contient une FHWInventoryMaster avec un TArray<FHWInventoryItem>.

L'EquipmentInventory ajoute un TMap<FGuid, FActiveGameplayEffectHandle> (ActiveEquipmentEffects) qui suit les GE actifs appliqués par les pièces équipées — permet le retrait propre au déséquipement.

EEquipmentSlot (17 valeurs) Head, EarringRight, EarringLeft, Necklace, Chest, Belt, Cloak, BracerLeft, BracerRight, HandLeft, HandRight, RingLeft, RingRight, Pants, Boots, Crystal (+ None).
Réplication FastArrayDeltaSerialize FDoRepLifetimeParams avec bIsPushBased = true, Condition = COND_OwnerOnly. Callback OnRep_Inventory rafraîchit l'UI via ReloadDisplayItems.
API gestion d'items AddItem, AddNewItem, RemoveItem, GenerateInventoryItem (FGuid), FindItemIndexByGUID, FindItemInInventoryWithRoomInStack.
API équipement IsItemEquippable, IsSlotEmpty, GetSlotFromOrder, EquipAllItems (appelé au spawn pour restaurer l'équipement).
Intégration GAS ApplyEquipmentStats(FHWInventoryItem) applique un GE dynamique sur l'ASC ; RemoveEquipmentStats(FGuid) retire le GE associé. Mapping ECara → GAS Attribute via CaraToAttribute() couvre 22 caractéristiques (ressources vitales, attributs primaires, stats combat).
— Boundary avec Pipeline Item —

Cette page documente le composant UHWInventoryComponent et son intégration GAS. Le pipeline détaillé des items (DataTables DT_ItemData, structures FHWItemStaticDataStruct, système de loot, persistance JSON OWS, tiers de qualité) est traité dans Pipeline Item.

Anomalies connues

FindItemInInventoryWithRoomInStack jamais appelée dans AddItem (stacks multiples possibles). InSlotNumber legacy (non utilisé — Order est la vraie position). SerializeInventoryCompact/DeserializeInventoryCompact commentés (code mort). ItemLibrary (FInventoryItemTypes) coexiste avec ItemDataTable (FHWItemStaticDataStruct) — double système.

Progression Component

UHWProgressionComponent · Moteur d'Héritage
Conceptuellement — moteur d'Héritage (Couche 4)

Techniquement, UHWProgressionComponent reste un système d'unlocks cachés déclenchés par les événements gameplay (kills, réactions, combos, visites, stats). Conceptuellement, après la refonte 2026, c'est le moteur d'Héritage de la Couche 4 — c'est ici qu'on enregistre les titres permanents, recettes, lore entries, accès de zone qui jalonnent l'identité durable du joueur.

Monté sur AHWGASPlayerCharacter. Pour la couche 3 (L'Accord 0–100 % par ère), 3 nouveaux types d'EHWConditionType sont prévus post-V4 : AccordReached (palier 25/50/75/100), EraConcorded (titre permanent à 100 % en fin d'ère), SouffleSurvived (trace dans Héritage à chaque cycle cosmique traversé). Voir Architecture (Migration Accord).

EHWConditionType (11 valeurs) MasteryLevel, KillCount, ReactionCount, AbilityUseCount, LocationVisited, ItemObtained, QuestCompleted, StatThreshold, TimePlayed, ComboAchieved, Hidden (Blueprint custom). Stockage par clé composite "ConditionType_SubjectTag" (ex : "0_Weapon.Sword").
EHWConditionVisibility (4 valeurs) Visible (« 10/50 kills d'orcs »), Hint (« Maîtrisez davantage l'épée… »), Hidden (rien — révélé au déverrouillage), RevealOnProgress (caché → révélé à 50 %). Préserve la mécanique « découverte organique » canon.
UHWUnlockDefinition (DataAsset) FGameplayTag UnlockID, EHWConditionOperator ConditionOperator (AND/OR), TArray<FHWUnlockCondition>, TArray<FHWUnlockableReward>, TArray<FGameplayTag> PrerequisiteUnlocks, bool bCompletelyHidden.
EHWRewardType (10 valeurs) Ability, PassiveEffect, WeaponCombo, Recipe, Title, Emote, LoreEntry, StatBonus, AccessToArea, CustomReward. Couvre tous les types d'Héritage canonique.
API principale IncrementProgress(Type, SubjectTag, Amount), SetProgress, IsUnlocked, GetProgress, MarkLocationVisited, MarkComboAchieved, SerializeProgression/DeserializeProgression (JSON OWS).
Réplication TMap runtime + TArray répliqué (Rep_ProgressionData) — workaround pour les TMap non répliquées nativement par UE.
Délégués FOnUnlockAchieved(UnlockID, Rewards[]) — notifie l'UI pour afficher la récompense ; FOnProgressUpdated(ConditionType, SubjectTag, NewProgress) — utilisé en interne pour les vérifications de seuil.
— Flux d'intégration combat —

Sur kill : IncrementProgress(KillCount, EnemyTag, 1.0f). Sur réaction élémentaire : IncrementProgress(ReactionCount, ElementTag, 1.0f). Sur progression Maîtrise : SetProgress(MasteryLevel, WeaponTag, NewLevel). Le composant cascade automatiquement CheckAllUnlocks après chaque incrément.

Quest Component

UHWQuestComponent · Quêtes visibles
Acceptation, suivi, complétion des quêtes

UHWQuestComponent pilote le cycle de vie des quêtes visibles du joueur (par opposition aux unlocks cachés du Progression Component). Monté sur AHWGASPlayerCharacter. Les définitions vivent dans des UHWQuestData (DataAssets) — workflow détaillé dans Pipeline Quest.

EHWQuestType (6 valeurs) MainStory, Side, Daily, Weekly, Hidden, Chain.
EHWQuestStatus (6 états) Unknown → Discovered → Active → Completed (ou Abandoned / Failed). Codes 0–5.
API principale AcceptQuest(QuestID), AbandonQuest, UpdateQuestProgress(Type, SubjectTag, Amount), DiscoverQuest, queries GetQuestStatus/IsQuestActive/GetActiveQuests/GetQuestObjectives, SerializeQuests/DeserializeQuests.
Délégués OnQuestAccepted, OnQuestCompleted(QuestID, Rewards), OnQuestObjectiveUpdated, OnQuestDiscovered.
Convention de tags Quest.NomQuete (identifiant base), .InProgress, .Completable, .Completed — partagés avec UHWNPCComponent::HasQuestForPlayer().
AHWLocationTrigger Volume de détection (BoxComponent 500×500×200 cm) avec FGameplayTag LocationTag. OnOverlap (serveur) appelle ProgressionComponent->MarkLocationVisited + QuestComponent->UpdateQuestProgress(LocationVisited, LocationTag, 1.0f) — pont entre exploration et progression.
Refonte 2026 — récompenses Accord/Héritage

Le composant continue d'appliquer FHWQuestReward à la complétion. Conceptuellement, l'ExperienceReward (int) sera réinterprétée comme AccordGain sur UHWProgressionComponent::CurrentEraAccord (Couche 3) ; les items et titres alimentent l'Héritage (Couche 4). Refonte sémantique seule en V3 — voir Architecture (Migration Accord).

Anomalies documentées (8)

Récompenses XP/Or seulement loggées (jamais accordées) ; DiscoveryConditions jamais vérifiées (Hidden quests jamais auto-découvertes) ; TimeLimitSeconds jamais utilisé ; RequiredLocation commenté TODO ; PrimaryAssetType non enregistrés (AssetManager peut ne pas découvrir les assets) ; DiscoveryConditions + NextQuestInChain non liés (Hidden-chain jamais découvertes) ; Unlock → Quête non notifié (progression ↔ quêtes unidirectionnel) ; TMap non répliquée nativement (workaround TArray).

Player Controller

AHWPlayerController · AHWLoginPlayerController
Orchestration centrale

AHWPlayerController est le point d'orchestration entre les systèmes : il porte les deux instances UHWInventoryComponent (Bag + Equipment), route les actions de haut niveau (interaction, voyage, sauvegarde), et communique avec le backend OWS via OWSPlayerControllerComponent.

AHWLoginPlayerController gère le flux de connexion et de sélection de personnage avant l'entrée en jeu. Détails OWS et migration Backend dans la page Backend OWS.

Interact Déclenche l'interaction avec l'IInteractable le plus proche (coffre, PNJ, porte). L'API IInteractable et ses implémentations sont documentées dans Code UI (Interactables).
TravelToZone Initie le voyage vers une autre zone — communique avec OWS pour le transfert de serveur. Voir Backend OWS pour le protocole.
SaveCharacterCustomization Persiste les données d'apparence (morphologie, couleurs, cosmétiques) côté serveur via FHWCharacterAppearanceCE.
SaveWeaponMastery Sauvegarde les niveaux de Maîtrise par type d'arme. Note canon : la courbe XP × 1.15^N actuelle sera remplacée par 5 paliers discrets (Novice → Maître) — voir Pipeline Combo et Migration Accord.
SaveCharacterProgression Persiste l'ensemble de la progression — stats brutes, compteurs cachés (Progression Component), unlocks obtenus, à terme Accord d'ère et Ères Concordées.
HandleDialogueAction Route les actions de dialogue entrantes vers le UHWDialogueComponent approprié. Le composant Dialogue lui-même est documenté dans Pipeline NPC.

GameMode et Infrastructure

AHWGameMode · UHWAssetManager
Couche d'amorçage

AHWGameMode étend AOWSGameMode (Open World Server). C'est ici que sont exposées les 6 TSubclassOf<UGameplayEffect> consommées par UHWCombatAttributeSet::SetupGameplayEffects() (Cold, Burning, Wet, Electrified, Frozen, Charged) — voir Code GAS pour le détail. UHWAssetManager remplace l'AssetManager par défaut pour exécuter les tâches de démarrage (initialisation des tags via FHWGameplayTags::InitializeNativeTags, chargement asynchrone des DataAssets).

AHWGameMode Étend AOWSGameMode. Configure les 6 GE d'états élémentaires consommés par l'AttributeSet. BP_HybeliorGameMode doit être le GameMode actif sinon les GE ne se chargent pas (risque silent fail documenté). GameMode · OWS
UHWAssetManager AssetManager custom. StartInitialLoading() initialise le singleton FHWGameplayTags (93 tags natifs en 17 catégories) et déclenche les tâches de démarrage personnalisées du projet. AssetManager · Init
UHWJsonSerialization Utilitaires de sérialisation JSON pour la conversion bidirectionnelle entre les structures C++ et le format JSON OWS. Utilisé par les SerializeInventory/SerializeProgression/SerializeQuests. JSON · Persistance
UHWCharacterCustomComponent Supprimé depuis 2026-04-07. Ses structs FHWMaterialSet et FHWAnatomyProfile ont migré vers HWCharacter.h. La personnalisation d'apparence est désormais portée par FHWCharacterAppearance/FHWCharacterAppearanceCE directement sur AHWCharacter. Supprimé · Refactor
