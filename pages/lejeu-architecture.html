Architecture technique du projet HybeliorWorld

HybeliorWorld est un projet Unreal Engine 5.4 construit autour du Gameplay Ability System (GAS) pour la gestion des compétences, effets et attributs de combat. L'architecture MMO repose sur Open World Server (OWS), un backend .NET en microservices qui gère l'authentification, la persistance des personnages, les instances de zones et la communication inter-serveurs.

Le projet s'organise autour d'un module Runtime unique : HybeliorWorld. La base de code C++ compte environ 72 fichiers (répartis entre Public et Private), complétés par plus de 35 679 assets Blueprint couvrant les abilities, les interfaces, le PCG, les GameplayEffects et l'ensemble du contenu de jeu.

Moteur Unreal Engine 5.4 — Nanite, Lumen, World Partition, Enhanced Input, CommonUI.
Gameplay Framework Gameplay Ability System (GAS) — Abilities, GameplayEffects, GameplayCues, AttributeSets, GameplayTags.
Backend MMO Open World Server (OWS) — API REST .NET, microservices (auth, characters, instances, global data), base de données persistante.
Module Runtime HybeliorWorld — module unique contenant l'ensemble de la logique C++ du jeu, organisé en 14 sous-systèmes.
Code C++ ~72 fichiers source répartis entre les dossiers Public/ (headers) et Private/ (implémentation).
Assets Blueprint 35 679+ assets — Blueprints, DataAssets, DataTables, GameplayAbilities, GameplayEffects, GameplayCues, Widgets, Maps.

Plugins et Dépendances

11 plugins majeurs
Écosystème de plugins

Le projet s'appuie sur un ensemble de plugins Epic officiels et tiers pour couvrir les besoins d'un MMO open-world complet : combat, réseau, IA, génération procédurale, environnement aquatique et interfaces.

GameplayAbilities Plugin Epic officiel — Gameplay Ability System complet : Abilities, Effects, Cues, AttributeSets, Tags, Tasks. Coeur du système de combat et de compétences.
ReplicationGraph Optimisation de la réplication réseau pour les environnements massivement multijoueurs. Gestion spatiale des acteurs répliqués selon la distance et la pertinence.
OWSPlugin Plugin client Open World Server — communication avec le backend REST, gestion des sessions, travel entre zones, persistance des personnages côté serveur.
CommonUI Framework UI d'Epic pour la gestion multi-plateforme des interfaces. Navigation par stack, support gamepad natif, gestion des focus et des couches d'UI.
TargetingSystem Système de ciblage avancé — sélection de cibles par filtres (distance, angle, type, faction), utilisé par le GAS pour les abilities et les GameplayEffects.
EnhancedInput Système d'input UE5 — Input Actions, Input Mapping Contexts, modifiers et triggers. Support clavier/souris, manette et multi-périphérique.
PCG (Procedural Content Generation) Génération procédurale de contenu environnemental — placement de végétation, rochers, détails de terrain sur les cartes de 20 à 50 km.
Oceanology Plugin tiers — simulation d'océan dynamique avec vagues, courants, buoyancy, rendu sous-marin et interactions physiques.
Riverology Plugin tiers — système de rivières procédurales avec flux directionnel, écume, interactions avec le terrain et connexion au système Oceanology.
LiveLink Pipeline d'animation temps réel — connexion avec des outils externes (Maya, MotionBuilder, capture faciale) pour le streaming d'animation en direct dans l'éditeur.
AIModule Module IA natif Unreal — Behavior Trees, Blackboard, EQS (Environment Query System), AI Perception. Base de l'IA des mobs et PNJ.

Structure des Modules

14 systèmes majeurs · ~72 fichiers C++
Organisation du code source

Le module HybeliorWorld est structuré en 14 sous-systèmes, chacun regroupant ses classes dans les dossiers Public/ (headers) et Private/ (implémentation). Le nombre de fichiers indiqué correspond au total headers + sources pour chaque système.

AbilitySystem · 17 fichiers Coeur du GAS — implémentation des GameplayAbilities, calcul de dégâts (UHWDamageExecCalc), AttributeSets (UHWAttributeSetBase, UHWCombatAttributeSet), AbilitySystemComponent custom, Ability Tasks spécialisés, GameplayEffects et GameplayCues.
UI · 14 fichiers Systèmes de widgets — HUD principal, menus, barres de compétences, inventaire UI, fenêtres de dialogue, notifications. Basé sur CommonUI avec des widgets C++ exposés aux Blueprints.
Character · 4 fichiers Classes de personnages de base — AHWCharacter (base avec apparence et ciblage), AHWGASCharacter (intégration GAS, attributs de combat). Hiérarchie extensible pour joueurs et mobs.
Combat · 3 fichiers Système de combos et enchaînements, maîtrise d'arme progressive, réactions élémentaires entre GameplayEffects. Gestion du momentum et des états de combat.
Input · 3 fichiers Gestion des entrées joueur via Enhanced Input — Input Mapping Contexts, binding dynamique des actions, support multi-périphérique (clavier/souris, manette).
Interactables · 4 fichiers Objets interactifs du monde — conteneurs, portes, Supply Pods, leviers. Interface commune IHWInteractable avec détection de proximité et feedback visuel.
AI · 2 fichiers Tasks de Behavior Tree custom et intégration avec le AIModule. Logique de décision des ennemis, patrouille, aggro et comportements de groupe.
Inventory · 2 fichiers Système de gestion d'inventaire — items, stacks, équipement, transferts entre conteneurs. Données persistées via OWS.
MobManager · 2 fichiers Spawning et gestion des ennemis — pools de mobs, respawn timers, densité dynamique selon la zone et la population de joueurs.
NPC · 2 fichiers Comportement des PNJ non-hostiles — routines quotidiennes, dialogues, interactions marchandes, réactions contextuelles au joueur.
Progression · 1 fichier Système de progression par pratique — calcul des gains de maîtrise, décroissance, seuils de déblocage, intégration avec les GameplayTags.
Loot · 1 fichier Système de loot — tables de drop, rareté, calcul contextuel des récompenses selon le type d'ennemi et la zone.
Quest · 1 fichier Système de quêtes — suivi des objectifs, conditions de complétion, récompenses, intégration avec le système de factions et de progression.
World / Portals · 2 fichiers Téléportation et gestion des locations — portails entre zones, travel inter-serveurs via OWS, points de spawn, World Partition streaming.

Hiérarchie des Personnages

Héritage C++ · 5 classes
Chaîne d'héritage des classes Character

L'architecture des personnages suit une hiérarchie d'héritage stricte, partant de la classe de base Unreal ACharacter jusqu'aux spécialisations joueur et mob. Chaque niveau ajoute une couche de fonctionnalité sans dupliquer de logique.

ACharacter Classe de base Unreal Engine — CharacterMovementComponent, CapsuleComponent, SkeletalMesh. Gère le déplacement physique, la gravité, le networking de base. UE5 · Base
AHWCharacter Classe de base HybeliorWorld — système d'apparence personnalisable, composant de ciblage (lock-on), animations de base, interface d'interaction. Tous les personnages du jeu héritent de cette classe. Apparence · Ciblage
AHWGASCharacter Intégration complète du GAS — AbilitySystemComponent, AttributeSets (vie, mana, endurance, stats de combat), application et réception de GameplayEffects, GameplayTags d'état. Classe parente commune aux joueurs et aux mobs. GAS · Attributs · Combat
AHWGASPlayerCharacter Spécialisation joueur — gestion des inputs (Enhanced Input), caméra troisième personne, système d'équipement (armes, armure, accessoires), barre de compétences, inventaire, intégration UI/HUD, persistance via OWS. Joueur · Input · Équipement
AHWGASMobCharacter Spécialisation ennemi — contrôleur IA (Behavior Tree + Blackboard), système de loot (tables de drop), intégration avec le MobManager (spawning, respawn, pools), AI Perception pour la détection des joueurs. IA · Loot · Spawner
— Schéma d'héritage —

ACharacter → AHWCharacter (apparence, ciblage) → AHWGASCharacter (GAS, attributs de combat) →
    ├── AHWGASPlayerCharacter (input, caméra, équipement, UI)
    └── AHWGASMobCharacter (IA, loot, spawner)

Structure du Répertoire Content

6 dossiers principaux
Arborescence des assets

Le dossier Content/ du projet est organisé par domaine fonctionnel. Les assets Blueprint, DataTables, GameplayEffects, Widgets et Maps sont séparés pour faciliter le versioning et le travail collaboratif.

AbilitySystem/ Coeur du GAS côté assets — sous-dossiers : Abilities/ (GameplayAbilities Blueprint), GEs/ (GameplayEffects : buffs, debuffs, dégâts, regen), GameplayCues/ (effets visuels et sonores déclenchés par les tags), Projectiles/ (projectiles magiques et physiques), Tags/ (GameplayTag DataTables).
BP/ Blueprints principaux — sous-dossiers : Game/ (GameMode, GameState, PlayerState), HUD/ (widgets d'interface en jeu), Inventory/ (système d'inventaire BP), Login/ (écran de connexion OWS, sélection de personnage), PCG/ (graphes de génération procédurale), Portals/ (acteurs de téléportation).
Input/ 28 Input Actions définies (mouvement, combat, interaction, UI, caméra, abilities) avec leurs Input Mapping Contexts pour clavier/souris et manette. Modifiers et Triggers configurés par action.
Maps/ Mondes multiples utilisant World Partition — cartes allant de 20 km à 50 km de diamètre. Streaming par cellules, niveaux de données (Data Layers) pour le contenu saisonnier ou événementiel.
Interactables/ Assets d'objets interactifs — Containers/ (coffres, caisses, armoires), Doors/ (portes avec états verrouillé/ouvert), SupplyPods/ (capsules de ravitaillement, récompenses de zone).
_HWAssets/ Assets artistiques et médias — Characters/ (meshes, rigs, animations des personnages), Audio/ (musique, SFX, ambiances), Icons/ (icônes d'items, compétences, UI), FX/ (Niagara particles, post-process), Environment/ (meshes de terrain, végétation, architecture).

Configuration

INI · GameplayTags · Enhanced Input
Fichiers de configuration clés

La configuration du projet est répartie entre les fichiers .ini d'Unreal et les systèmes de tags/input intégrés au GAS. Les paramètres réseau OWS, les tags de combat et les mappings d'input sont les trois piliers de la configuration.

DefaultGame.ini Configuration OWS — URL de l'API backend, clés d'authentification, paramètres de session, timeouts réseau. Paramètres GAS globaux : modes de prédiction, réplication des GameplayEffects, politique de tags.
DefaultGameplayTags.ini Définition de l'arborescence complète des GameplayTags utilisés par le projet : CombatTags (états de combat, types de dégâts, conditions), InputTags (binding GAS des actions), AbilityTags (activation, cooldown, blocage), EquipmentTags (slots, types d'arme, rareté).
Enhanced Input Configuration multi-périphérique — Input Mapping Contexts séparés pour clavier/souris et manette, avec priorités de contexte (gameplay, UI, véhicule, dialogue). Support du remapping en jeu par le joueur.
— Stack technique résumé —

Client : Unreal Engine 5.4 · C++ (HybeliorWorld module) · Blueprints · GAS · Enhanced Input · CommonUI · World Partition · Nanite · Lumen · PCG · Niagara

Réseau : OWSPlugin · ReplicationGraph · Dedicated Servers · Zone-based instancing · Server travel

Backend : Open World Server (.NET) · REST API · Microservices (Auth, Characters, Instances, GlobalData) · Base de données persistante
